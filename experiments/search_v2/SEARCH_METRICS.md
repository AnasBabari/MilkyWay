# Search metrics contract — implementation pending baseline selection

The existing runtime returns move, score, completed depth, total visited nodes, elapsed seconds, abort state and TT cutoffs mislabeled as hits. Do not populate unmeasured counters with invented zeros. Machine-readable contract: SEARCH_METRICS.json.

Suite preparation completed: probe_suite_01.json contains 240 distinct valid positions, SHA256 b8bf9134c965521324c9cf7231c16c0fdaf079376f8d25249bb0a314f169aa01. Categories overlap: 118 endgames, 128 passed-pawn positions, 33 check evasions, 17 promotion positions, 64 quiet positions, 105 recorded-loss positions and two curated possible-zugzwang probes. Source hashes and legal history are retained. build_probe_suite.py passed ruff; instrumented search execution remains pending.

1. Freeze an ordered suite of at least 200 distinct positions before evaluating a Search V2 change. Include quiet openings/middlegames, tactical exchanges, checks/king attacks, sparse endings, passed pawns, possible zugzwangs, promotions/underpromotions, material imbalances and positions from recorded losses. Tag provenance and categories explicitly; heuristic tags are not engine-certified tactical truth. Preserve the move history when testing repetition. This is a development suite, never an independent confirmation bank.
2. Use deterministic fixed-depth measurements with a generous safety deadline, fixed coefficient/weights/history/TT settings and a warmed module. Incomplete searches are reported separately, not compared as equal-depth savings. Record end-to-end time including allocations as well as search-kernel time. Reverse execution order in timing repeats after controlled-load access is available.
3. Add instrumentation only in an isolated diagnostic copy of the selected frozen baseline. Keep a disabled path and prove fixed-depth move/score/node parity against the baseline. Check counter invariants: qnodes <= nodes; cutoff hits <= context-valid hits <= position hits <= probes; first-move beta cutoffs <= beta cutoffs; re-searches <= attempts where defined.
4. Record nodes and qnodes separately, NPS, generated/searched moves, maximum ply/q-depth, TT probes/position hits/context hits/cutoffs, beta and first-move beta cutoffs, PVS scouts/re-searches, LMR attempts/re-searches, null attempts/cutoffs/verifications, futility/RFP/LMP/SEE skips, aspiration fail-high/fail-low and deadline/cap hits. Counters for absent mechanisms are explicitly not applicable.
5. Report per-position deltas and aggregate sums/medians, outliers, tactical move/score changes and completion rates. Node reduction is not a strength gate. A speedup that loses tactical correctness must not advance merely because its NPS looks good.
6. After choosing a candidate, remove diagnostic overhead or compile it away and verify the exact production runtime again. Freeze that runtime before games. Never edit a runtime participating in a screen.
